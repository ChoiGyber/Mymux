# Mymux 모바일 동반 앱 설계 초안

## 목적

휴대폰에서 데스크톱 Mymux가 이미 실행 중인 로컬 셸 또는 SSH 작업에 다시 연결한다. 모바일은 세션을 새로 실행하거나 `session.json`의 화면 상태를 재생하는 대신, 데스크톱 PTY 소유 프로세스에 인증된 클라이언트로 붙는다.

이 문서는 전용 모바일 앱과 데스크톱 연결의 MVP 범위 및 설계 근거를 기록한다. 구현은 LAN 전용으로 진행 중이며, 아래 완료 기준의 실기기 검증까지 마쳐야 제품 준비가 끝난다.

## 현재 코드에서 확인한 기반

- `crates/mycli-desktop/src/main.rs`는 Tauri UI와 별도 `--mymux-pty-server` 프로세스를 실행한다.
- `crates/mycli-desktop/src/pty_server.rs`는 Windows named pipe 또는 Unix domain socket을 통해 GUI와 PTY 서버 간 요청을 중계한다. 이 통로는 모바일용 TCP/WebSocket 서버가 아니다.
- `crates/mycli-desktop/src/terminal.rs`의 PTY 인터페이스는 spawn, read, write, resize, close를 제공한다. 출력 이력은 세션당 1 MiB로 제한되며 모바일 읽기는 한 배치 최대 64 KiB로 제한할 수 있다.
- 앱 종료 시 프런트엔드가 보존할 세션 키를 PTY 서버에 넘길 수 있다. 따라서 창 종료 뒤에도 세션을 유지하는 토대는 있지만 모바일 인증과 원격 재접속은 구현되어 있지 않다.
- 현재 모바일 네트워크 전송 프로토콜과 인증 게이트웨이는 구현되지 않았다.

## 세션 목록 드래그와 에이전트 접기

세션 사이 이동은 세션 목록을 출발점으로 할 수 있어야 한다. 사용자가 목록의 세션 행을 길게 누른 뒤 상단의 목적 탭에 놓으면 해당 세션을 그 탭으로 옮긴다. 탭 안의 기존 세션 행에 놓으면 그 위치 앞이나 뒤로 배치한다. 터미널 pane의 분할/재배치와 탭 이동은 서로 다른 동작으로 유지한다.

모바일에서는 길게 누르기로 드래그를 시작하고, 드래그 중 목적 탭을 강조한다. 놓기 전에 목적 탭 이름과 이동할 세션 이름을 확인할 수 있어야 한다. 세션이 마지막으로 남은 탭에서 빠져나가 탭이 비게 되면 그 탭을 정리한다. 실수로 세션을 닫거나 새 셸을 만들지 않도록, 이동은 기존 PTY 인스턴스를 그대로 재배치한다.

한 세션에 연결된 에이전트 목록은 세션 행의 별도 접기/펴기 컨트롤로 숨길 수 있어야 한다. 에이전트 목록을 접어도 세션 자체는 목록에 남고, 실행 중/전체 개수를 세션 행에 표시한다. 접기 상태는 세션별로 관리해 다른 세션에 영향을 주지 않게 한다. 작은 화면의 모바일 앱에서는 기본적으로 접은 상태로 시작하고, 사용자가 열었을 때만 에이전트 상세를 표시한다.

데스크톱 구현에는 이미 이 동작의 기반이 있다. [app.js](../../crates/mycli-desktop/frontend/app.js)는 세션 행에서 드래그해 다른 탭이나 세션에 놓는 이동을 처리하며, 세션별 에이전트 목록 접기 토글도 제공한다. 모바일 앱은 별도의 터치 입력 경로로 같은 세션 재배치와 에이전트 접기 의미를 제공한다.

## 제안하는 MVP

| 항목 | 제안 |
|---|---|
| 클라이언트 | Android와 iOS용 단일 코드베이스 전용 앱 |
| 첫 연결 범위 | 사용자가 같은 LAN에서 직접 연결 |
| 페어링 | 데스크톱 앱이 짧은 수명의 QR 페어링 정보를 표시하고 모바일이 스캔 |
| 세션 동작 | 활성 세션 목록 조회, 기존 세션 재접속, 출력 따라가기, 키보드 입력, 크기 조정 |
| 세션 목록 | 세션 행을 길게 눌러 목적 탭으로 이동, 한 세션의 에이전트 목록 접기/펴기 |
| 생명주기 | 모바일 연결 종료는 PTY를 종료하지 않음. 명시적인 세션 종료만 PTY close 수행 |
| 외부 접속 | MVP에서 제외. 추후 VPN 또는 릴레이 방식으로 별도 결정 |
| 기본 권한 | 페어링된 앱에 세션 목록과 읽기/쓰기 허용. 기기 해제는 데스크톱에서 가능 |

## 구성

```text
모바일 앱
  ├─ 네이티브 페어링/기기 자격 증명 저장
  ├─ WebSocket 연결 및 재연결
  └─ 터미널 렌더링 뷰
          │ WebSocket 운반 + Noise 핸드셰이크/암호화 데이터
          ▼
Mymux 데스크톱 연결 게이트웨이
  ├─ 페어링, 기기 인증, 권한 및 요청 검증
  ├─ 모바일 프로토콜과 내부 PTY 명령 간 어댑터
  └─ 기존 로컬 IPC를 통해 PTY 소유 프로세스에 요청
          ▼
PTY 소유 프로세스 → 기존 로컬 셸 또는 SSH 세션
```

모바일 네트워크 요청을 기존 named pipe에 직접 연결하거나 named pipe를 TCP로 포워딩하지 않는다. 게이트웨이만 외부 입력을 받으며, 기존 PTY 서버 IPC는 로컬 경계 안에 둔다.

## 연결 및 페어링 흐름

1. 사용자가 데스크톱에서 “모바일 연결”을 켠다. 기본 상태는 꺼짐이다.
2. 데스크톱은 무작위 일회용 페어링 nonce와 만료 시각을 만들고 QR에 LAN 주소, 포트, Noise 서버 정적 공개키, nonce를 담는다.
3. 모바일은 연결 코드를 검사하고, Noise 핸드셰이크 첫 메시지에 nonce를 실어 보낸다. 데스크톱은 핸드셰이크에서 정적키를 확인하고 QR의 서버 키와 대조한다. 페어링은 데스크톱 사용자의 확인을 받은 뒤 완료한다.
4. 페어링 완료 시 서버와 모바일은 기기별 장기 자격 증명을 발급·저장한다. QR nonce는 즉시 폐기한다.
5. 이후 접속은 기기별 자격 증명으로 인증하고, 모바일은 제한된 크기의 이력부터 읽은 뒤 offset 기반으로 증분 출력을 구독한다.
6. 사용자는 데스크톱의 기기 목록에서 개별 기기를 해제할 수 있다. 토큰 해제는 다음 연결부터 즉시 적용한다.

QR은 장기 비밀번호가 아니어야 하며, 화면 캡처·재사용에 대비해 짧은 만료, 1회 교환, 사용자 승인, 재사용 방지를 적용한다. 기기 토큰은 플랫폼 보안 저장소에 보관하고 로그나 분석 이벤트에 기록하지 않는다.

## 모바일 프로토콜 초안

JSON 메시지를 WebSocket 프레임으로 주고받는다. WebSocket은 LAN 연결의 운반 수단으로만 쓰고, 모든 애플리케이션 메시지는 Noise 전송 암호문으로 감싼다. QR의 서버 정적 공개키를 Noise 핸드셰이크 결과와 대조하며 인증 실패나 키 불일치 때 평문 대체 경로를 두지 않는다. 각 복호화된 메시지는 버전과 요청 ID를 포함한다. 입력은 텍스트와 제한된 크기만 허용하고, resize 값과 세션 ID는 서버에서 검증한다.

초기 메시지 종류:

- `hello`: 프로토콜 버전 및 클라이언트 버전 협상
- `session.list`: 모바일에서 접근 가능한 세션 메타데이터 조회
- `session.attach`: 세션 ID와 출력 offset으로 재접속
- `terminal.output`: 출력 데이터, 다음 offset, 이력 잘림 여부 전달
- `terminal.input`: 입력 데이터 전달
- `terminal.resize`: 열·행 전달
- `session.detach`: 연결 해제만 수행
- `session.close`: 사용자의 명시적 세션 종료
- `error`: 안정적인 오류 코드와 요청 ID 전달

자격 증명은 모든 WebSocket 세션에서 인증돼야 한다. Origin 검사만으로 인증을 대체하지 않는다. 서버는 메시지·프레임 크기, 동시 연결 수, 입력 속도, 세션별 구독 수를 제한해야 한다.

## 보안 및 동시 제어 규칙

- 바인딩 주소는 사용자가 선택한 인터페이스로 제한하고, 기본값을 무조건 `0.0.0.0`으로 열지 않는다.
- 네트워크 수신은 명시적으로 켰을 때만 시작한다. 방화벽 안내와 현재 연결 상태를 데스크톱에 보여준다.
- 서버 인증과 데이터 기밀성은 TLS 대신 Noise 전송 암호화로 제공한다. Expo SecureStore는 향후 기기 키 저장에 쓸 수 있다. Noise 라이브러리는 Expo/React Native에서 Android·iOS 모두 지원하고 handshake 및 transport 벡터가 검증된 구현을 사용하며, 자체 암호 알고리즘 코드는 작성하지 않는다. 패킷 길이·주소·시각 같은 전송 메타데이터는 LAN에서 관찰될 수 있다.
- 기기별 식별자·권한·생성 및 마지막 접속 시각을 관리하고 기기별 해제를 지원한다.
- 모든 기기는 기본적으로 입력할 수 있게 하되, 동시 입력은 직렬화하고 데스크톱에 모바일 제어 중임을 표시한다. 읽기 전용 모드는 MVP에서 선택 옵션으로 둘 수 있다.
- 임의 파일 접근, 명령 실행 API, 자격 증명 전달 API는 이 프로토콜에 노출하지 않는다. 터미널 입력·출력 외 기능은 별도 권한 설계가 필요하다.
- 출력은 기존 1 MiB 이력 한도와 별도로 모바일 전송 batch 크기와 속도를 제한한다. 오래된 offset은 잘림 상태와 새 시작 offset을 반환한다.
- 연결 중단, 앱 백그라운드 전환, 데스크톱 재시작에서 PTY 생명주기를 변경하지 않는다. 재접속 때 유효한 세션이 없으면 재생성 대신 분명한 오류를 보여준다.

## 앱 기술 선택

단일 코드베이스는 **Expo SDK 58 + React Native**로 시작한다. 현재 앱은 Expo Router 화면, 네이티브 탭, 터치 기반 세션 이동과 접기 UI를 제공한다. xterm.js와 fit addon을 로컬 번들에 넣은 WebView 터미널을 연결해 ANSI 화면 처리, 키 입력, PTY resize 경로를 구현했다. 실제 Android/iOS 기기에서 한글 IME, 키 조합, 붙여넣기, 접근성 및 백그라운드 복귀는 아직 검증해야 한다.

첫 기술 검증의 통과 조건:

- Android와 iOS에서 한글 조합 입력이 중복 전송되지 않는다.
- Ctrl, Alt, Esc, 화살표, Tab, Ctrl+C 등 터미널 키를 보낼 수 있다.
- 화면 크기 변경이 기존 PTY에 반영되고 재접속 후 ANSI 화면이 깨지지 않는다.
- Noise 핸드셰이크에서 QR 서버 키를 확인하고, 생체/기기 잠금 기반 앱 재진입을 구현할 수 있다.

## 단계별 계획

1. **연결 설계 검증:** 현재 MVP 최소 OS는 iOS 18·Android 13으로 잠정 고정한다. [Torann Expo 모듈](https://github.com/stonygrey/torann/tree/main/reactnative/torann)은 해당 최소 버전과 공유 테스트 벡터를 제공한다고 문서화되어 있지만, upstream이 production-ready/독립 감사 상태를 보장하지 않으므로 보안 승인으로 간주하지 않는다. 데스크톱 호환 구현, 실제 기기 검증, 의존성 보안 검토를 완료하기 전에는 사용자 대상 모바일 연결을 활성화하지 않는다. 메시지 보호는 [Noise Protocol Framework](https://noiseprotocol.org/noise.html)의 핸드셰이크 및 transport 정의에 따른다.
2. **보안 코어:** 연결 게이트웨이, 일회성 페어링, 기기 자격 증명 저장·해제, 버전형 메시지 검증, 읽기 전용 연결부터 구현.
3. **전용 앱 MVP:** 페어링, 세션 목록, 기존 세션 attach, 출력, 모바일 입력, 재접속.
4. **제어와 배포:** 다중 기기 표시, 입력 제어 UX, Android/iOS 패키징·서명·업데이트, OS별 실제 기기 검증.
5. **외부 접속:** VPN 경로를 먼저 평가하고, 필요성이 확인되면 종단 간 암호화와 최소 메타데이터를 갖춘 릴레이를 별도 설계한다.

## 완료 기준

- 모바일이 새 셸을 만들지 않고 데스크톱의 기존 로컬 또는 SSH PTY에 재접속한다.
- 인증되지 않은 기기는 세션 목록, 출력, 입력 어느 것도 읽거나 실행할 수 없다.
- 해제된 기기의 자격 증명은 다시 사용할 수 없다.
- 앱 강제 종료와 네트워크 손실 후에도 데스크톱 세션은 유지되고, 재접속 시 제한된 출력 이력에서 이어진다.
- 세션 목록에서 세션을 다른 탭으로 옮길 수 있고, 에이전트 접기 상태는 세션별로 독립적이다.
- 세션 목록에 비밀 환경 변수, 인증 정보, 로컬 파일 경로 같은 불필요한 세부 내용이 노출되지 않는다.
- Android 및 iOS 실기기에서 입력 조합, 재연결, 화면 회전, 백그라운드 복귀를 확인한다.

## 미결정 사항

초기 기본안은 Android+iOS, LAN 전용, 페어링된 기기의 입력 허용, 외부 접속 미포함이다. 구현 착수 전에 다음 결정을 확인해야 한다.

1. 최초 출시 대상은 Android와 iOS 동시 지원인가, Android 우선인가?
2. LAN 전용 MVP로 시작해도 되는가, 첫 버전부터 외부 접속이 필수인가?
3. 전용 앱에서 허용할 범위는 터미널 조회·입력에 한정할 것인가?

## 구현 상태

- Expo 앱의 화면 골격과 탭 순서 드래그, 세션→탭 이동, 세션별 에이전트 접기 UI가 있다. 탭 순서와 현재 탭은 기기에 저장하며 연결 전에는 예시 세션을 실제 세션처럼 표시하지 않는다.
- PTY 소유자에 내부 sessionKey/숫자 ID와 별도인 UUIDv4 모바일 세션 ID 및 로컬 IPC 전용 목록/read/write/resize/close 연산을 추가했다. 데스크톱의 Claude transcript poller는 프롬프트를 제외한 하위 에이전트 요약을 PTY 소유자에 동기화하고, mobileList가 이를 반환한다. 입력은 16 KiB, 화면 크기는 열 20–500 및 행 5–200으로 제한한다. 네트워크 게이트웨이는 이 로컬 IPC 어댑터만 호출한다.
- 모바일 앱은 카메라 QR 스캔과 버전·사설 LAN 주소·포트·32바이트 서버 키/nonce·만료 시각 검사까지 구현했다. QR 계약은 `kind=mymux-pair`, `v=1`, `host`, `port`, base64url `serverKey`와 `nonce`, Unix epoch milliseconds `expiresAt`이다. Torann 기반 Noise XX 클라이언트 핸드셰이크에서 QR 서버 정적키 고정을 구현했고, Expo 설정을 iOS 18·Android API 33으로 지정했다. 암호화된 JSON RPC, 저장 기기 재접속·선택, 세션 목록, 제한된 PTY 출력 polling, 세션별 offset 유지·tail-follow, 여러 줄 입력/실행 분리, 로컬 번들 xterm.js 터미널, resize/명시적 종료 클라이언트를 구현했다. desktop PTY owner에는 명시적 시작/중지 가능한 LAN WebSocket gateway, persistent Noise server identity/승인 목록, QR SVG, 승인 대기 큐/UI와 해제 명령, 요청·operation별 필드 검증이 추가됐다. 사용자가 scan QR → desktop approve → device credential 저장 → live session attach 하는 경로가 코드로 연결됐으나, 실제 OS 기기·네트워크 런타임 검증, 터미널 IME·접근성 확인과 Torann 의존성 보안 검토는 남아 있다.
- 이 개발 환경에는 로컬 Android SDK/Java 및 iOS 빌드 도구가 확인되지 않았다. 현재 단계에서는 앱 번들·실기기 실행을 검증할 수 없다.

플랫폼 기본안은 Android+iOS, LAN 전용, 페어링된 기기의 입력 허용, 외부 접속 미포함으로 둔다. 게이트웨이 코드와 모바일 클라이언트는 연결되어 있으나, 사용자 대상 배포 전 프로토콜·의존성 보안 검토와 실제 기기 검증을 완료해야 한다.
