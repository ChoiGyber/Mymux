# 세션별 마이크 버튼 설계 (2026-11-20)

## 의도

지금 음성 입력은 상단 🎙 팝오버의 녹음 버튼이나 Ctrl+Space로만 쓸 수 있고, 인식 결과는 항상 "현재 선택된 패인"으로 들어간다. 사용자는 세션(패인)마다 마이크 버튼을 두고, 그 버튼을 누르면 그 세션으로 인식 결과가 들어가기를 원한다.

## 결정 사항

사용자가 정한 것:

- 각 세션에 마이크 버튼을 둔다. 버튼을 누르면 인식 결과가 그 세션에 입력된다.
- 녹음 중에는 "녹음 중" 같은 글자 대신 **마이크 입력의 파장**이 보인다.

제안해서 승인받은 것:

- **위치:** 패인 상단 표시줄에서 분할 버튼 앞. 패인이 좁아져도 닫기 버튼처럼 숨기지 않는다.
- **조작:** 한 번 누르면 녹음 시작, 다시 누르면 멈추고 인식한다. Ctrl+Space(누르는 동안 녹음)와 팝오버 녹음 버튼은 그대로 둔다.
- **입력:** 인식 결과는 그 패인에 붙여 넣기만 하고 Enter는 누르지 않는다(기존과 동일).
- **동시 녹음:** 마이크가 하나이므로 한 번에 하나만 녹음한다. 다른 세션이 녹음 중일 때 누르면 진행 중인 녹음을 멈추고 인식한 뒤, 새 녹음은 시작하지 않는다.
- **설정:** 엔진·모델·언어는 상단 🎙 팝오버의 설정을 그대로 쓴다.

## 구현자 판단 (제가 정한 것)

- 파장은 버튼 자리에 그리는 작은 캔버스(약 56×16px)로, `AnalyserNode`의 시간 영역 신호를 매 프레임 그린다. 녹음이 끝나면 즉시 멈추고 오디오 처리를 닫는다.
- 인식하는 동안에는 글자 없이 버튼이 흐려지며 점이 움직이는 표시만 보인다. 인식이 끝나면 🎙로 돌아간다.
- 녹음·인식 로직은 팝오버 안에서 꺼내 패인 버튼, 팝오버 버튼, Ctrl+Space가 함께 쓰는 하나의 제어 객체로 만든다. 결과를 넣을 대상은 녹음을 시작할 때 정하고, 그 패인이 그사이 닫혔으면 넣지 않는다.
- 실패하면 지금처럼 알림(toast)으로 이유를 보여 준다.

## 하지 않는 것

- 마이크 장치 선택 기능(윈도우 기본 녹음 장치를 그대로 쓴다).
- 세션 목록(Sessions 패널) 행의 버튼.
- 인식 결과 뒤에 자동으로 Enter 보내기.

## 검증

헤드리스 Chrome의 가짜 마이크(`--use-fake-device-for-media-stream`)로 실제 `app.js`를 띄워, 패인 두 개 중 선택되지 않은 패인의 버튼으로 녹음하고, 파장 캔버스가 실제로 그려지는지(픽셀 변화)와 인식 결과가 그 패인에만 들어가는지 확인한다. 기존 하네스(`scripts/terminal-harness/run-all.mjs`)도 계속 통과해야 한다.
