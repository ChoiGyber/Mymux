## 2. TERM 수정 — `2848368`

- Dock·Finder·Linux 런처로 띄운 앱엔 `TERM` 이 없어 zsh 가 매 키마다 0열부터 다시 그림 → 명령이 흩어지고 autosuggestion 회색 힌트가 글자로 남고, 세션 복원 시 그 잔해가 재실행될 수 있었음.
- `terminal.rs` `pane_command` 에서 Unix 패인은 `TERM=xterm-256color` 강제(물려받은 값도 교체). Windows 는 `#[cfg(not(windows))]` 로 무접촉. 테스트 2개 추가, `cargo test -p mycli-desktop` 86개 통과.
- 작업 트리의 `terminal.rs` 가 CRLF 였음(리포는 LF) — LF 로 되돌린 뒤 커밋해 실제 변경 62줄만 반영.

## 3. 휠 wip 커밋 `725d4aa` 검증 → 되돌림 `5e8a670`

- 각 CLI 의 실제 모드 실측(PTY): Claude Code 2.1.285 fullscreen·Codex 0.159.3·OpenCode = **대체 화면 + 1003/SGR 트래킹**, Claude 기본 tui = **일반 화면·트래킹 없음**.

- 검증: 동봉 xterm 5.5.0 에 두 핸들러를 넣고 Chromium·WebKit 에서 시나리오별 비교. #40 에 코멘트.

## 5. #40 원인 규명 + Windows 우회 — `1def3a1`

- **원인(업스트림):** Claude Code fullscreen 렌더러(`tui: fullscreen`, 2026-05-06 이후 신규 사용자 기본값)는 **네이티브 Windows 에서 휠에 무반응** — Windows Terminal 포함 모든 터미널([anthropics/claude-code#85712](https://github.com/anthropics/claude-code/issues/85712), 수정 없이 stale 종료).
- **Mymux 쪽 정상 확인:** macOS PTY 에서 Claude fullscreen 에 Mymux 와 같은 `ESC[<64;…M` → 정상 스크롤. Codex 는 ConPTY 의 `MOUSE_EVENT` 레코드를 crossterm 이 직접 읽어 동작(ConPTY 소스로 경로 확인).
- **우회:** Windows + 대체 화면 + 마우스 트래킹 + Claude 소유 패인(`ctxSource === "claude"`, codex 아님)에서만 휠 → `ESC[5~`/`ESC[6~`(PgUp/PgDn, Claude 가 반 화면씩 스크롤). 휠 한 칸(100px) delta 당 키 1개, 터치패드 delta 누적, 이벤트당 최대 3개. 그 외 경로 무변경.
- 검증: `app.js` 실제 블록을 xterm 5.5.0(Chromium)에 넣어 6조합 × 4제스처, macOS PTY 에서 PgUp 스크롤 실측. **Windows 실기 미검증.**
- 참고: Claude Code 2.1.285 의 `!` 셸 모드는 출력이 모델에도 전달된다(테스트 중 짧은 Opus 응답 3회 소비). 로컬만으로 화면 채우려면 `/release-notes` → Show all.
