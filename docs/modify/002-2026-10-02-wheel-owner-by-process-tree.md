# Windows 휠 우회 — 패인 주인을 프로세스 트리로 판정

## 문제

v0.3.1 의 #40 우회(Windows + Claude fullscreen 패인에서 휠 → PgUp/PgDn)는 패인 주인을 화면 추정값 `t.ctxSource === "claude"` 로 판단했다. 이 값은 셸 프롬프트의 OSC 133 마크가 와야 초기화되는데 **CMD 와 ssh 는 마크를 보내지 않는다.** 그래서 같은 패인에서 Claude 를 끄고 Codex 를 켜면 Codex 가 계속 Claude 로 남고(`aiMode` 가 켜져 있어 Codex 감지도 막힘), Codex 의 휠까지 PgUp/PgDn 으로 바뀌었다.

조사: Claude Code 는 종료 시 아무 문구도 남기지 않고(재개 안내 없음) 모드만 끈다. 시작할 때도 같은 모드를 잠깐 껐다 켜서 모드 변화만으로는 종료를 구분할 수 없다.

## 해결

- **백엔드 `pty_ai_process(id)`** (`terminal.rs`): 패인 셸 PID(`PtySession.shell_pid`, spawn 시 기록)에서 프로세스 트리를 너비 우선으로 내려가 셸에 가장 가까운 추적 대상을 돌려준다 — `"claude"` / `"codex"`(npm 런처의 `codex-<triple>.exe` 포함) / `"ssh"`(ssh·plink·mosh, 원격에서 실행 중) / `null`. Claude 가 띄운 `codex exec` 같은 하위 프로세스는 더 깊어 가리지 못한다. Windows 는 `CreateToolhelp32Snapshot`, 그 외 OS 는 빈 표(항상 `null`).
- **프론트** (`app.js`): Windows 에서 대체 화면에 들어갈 때마다 질의해 `altOwner` 에 저장(나갈 때 초기화, 늦게 온 응답은 순번으로 버림). 휠 판단은 `altOwner` 가 있으면 그것만 본다(`claude` 일 때만 변환). 응답 전이거나 `null` 이면 기존 화면 추정으로 대체.
- 덤으로 고쳐진 것: **ssh 로 원격 Claude** 를 쓸 때(원격에선 휠이 정상) 더 이상 PgUp/PgDn 으로 바꾸지 않는다. **셸 alias 로 띄운 Claude** 도 프로세스로 인식돼 우회가 적용된다.
- 등록: `build.rs` APP_COMMANDS, `capabilities/default.json` `allow-pty-ai-process`, `main.rs` invoke_handler, `windows-sys` 에 `Win32_System_Diagnostics_ToolHelp`. 생성물(`acl-manifests.json`, `capabilities.json`, `desktop-schema.json`, `permissions/autogenerated/pty_ai_process.toml`) 커밋, `windows-schema.json` 은 HEAD 에서 desktop 과 동일했으므로 동기화.

## 검증

- Rust 단위 테스트 7개(`ai_process_tests`): 이름 분류, CMD 에서 Claude 뒤 node→codex, 다른 패인의 Codex 무시, Claude 하위의 codex 가 Claude 를 가리지 않음, ssh(자식/셸 자체), 일반 셸·없는 PID, PID 재사용 루프 종료. `cargo test -p mycli-desktop` 93개 통과(ACL 가드 포함).
- Windows 전용 스냅샷 코드: 같은 `windows-sys 0.59.0` 기능으로 별도 크레이트에서 `cargo check --target x86_64-pc-windows-msvc` 통과.
- 프론트: `app.js` 실제 블록을 xterm 5.5.0(Chromium)에 넣고 질의 응답을 바꿔 8개 시나리오 확인 — 화면=claude·프로세스=codex(문제 상황)에서 Codex 에 SGR 휠이 그대로 감, ssh 는 SGR, 프로세스=claude 면 PgUp/PgDn, `null` 이면 화면 추정, macOS 는 질의 0회·무변경.
- **Windows 실기 미검증** — CMD 패인에서 `claude` 종료 후 `codex` 실행 → 휠이 Codex 대화를 스크롤하는지 확인 필요.

## 체크

- UI 문자열 변경 없음(i18n 해당 없음). 설명서 영향 없음.
- macOS 가드 13/13, 벤더 tao 가드 6/6, `mac-patches/apply.sh --check` 정상.
- 새 코드 블록만 rustfmt 적용(파일의 기존 미포맷 부분은 손대지 않음).
