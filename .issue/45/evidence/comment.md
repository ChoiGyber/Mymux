빨간 박스가 드래그한 줄입니다. 왼쪽이 Claude Code 재현 패인(마우스 트래킹 ON), 오른쪽이 Codex 재현 패인(트래킹 OFF)이고, 두 패인에 완전히 같은 드래그를 수행한 직후입니다. 변경 전에는 왼쪽만 선택이 만들어지지 않았습니다.

## 원인

xterm 은 실행 중인 프로그램이 마우스 트래킹을 켜면 모든 버튼 이벤트를 그 프로그램에 넘기고, Shift 를 누른 드래그만 선택으로 인정합니다. 그래서 트래킹을 켠 패인에서는 평범한 드래그가 선택을 만들지 못하고, 선택이 없으니 기존 자동 복사도 돌지 않았습니다. 더 나쁜 것은 그 드래그가 프로그램에는 시작 열의 press 와 끝 열의 release, 즉 **엉뚱한 위치의 클릭 한 번으로 전달**됐다는 점입니다.

설치된 실행 파일을 훑어 어떤 모드를 쓰는지 확인했습니다.

- `claude.exe` v2.1.236 — 클릭 트래킹과 SGR, 대체 화면을 켜는 시퀀스를 갖고 있고 **모션 트래킹 시퀀스는 아예 없습니다**
- Codex 는 트래킹을 켜지 않습니다. 같은 앱에서 Codex 패인만 멀쩡했던 이유입니다

특정 PC 에서만 발생한 것도 이것으로 설명됩니다. 신고자 PC 의 Claude Code 가 그 화면에서 트래킹을 켜지 않았을 뿐, 켜는 순간 어느 PC 에서든 재현됩니다.

## 통합 검토에서 잡힌 것 — 첫 구현은 맥을 못 고쳤습니다

merge 직전 비판 검토가 이 수정을 막았고, 확인해보니 맞았습니다. xterm 이 "강제 선택" 으로 인정하는 조건이 플랫폼마다 다릅니다. 윈도·리눅스는 Shift 지만 **맥은 Option 이고, 그것도 `macOptionClickForcesSelection` 옵션이 켜져 있을 때만** 입니다. 이 옵션은 기본값이 꺼짐이고 이 앱은 켠 적이 없었습니다. 그래서 첫 구현이 재전달하던 Shift 는 맥에서 아무 효력이 없었습니다.

맥 경로를 수정 전/후로 각각 실측했습니다(`navigator.platform` 을 스푸핑해 xterm 과 앱이 동시에 맥으로 인식하게 만든 뒤, 수정 전은 `main` 트리를, 수정 후는 이 브랜치를 띄워 측정).

| 맥 | 드래그 결과 |
| --- | --- |
| 수정 전 (`main`) | 선택 없음 · 복사 안 됨 · 프로그램에 클릭 1회 오전달 — **윈도와 같은 증상이고, 맥엔 Shift 우회로조차 없었습니다** |
| 수정 후 | **선택됨 · 자동 복사됨 · 오전달 0** |

그래서 맥에서는 옵션을 켜고 Option 을 재전달합니다. 덤으로 맥 사용자는 이제 Option+드래그로도 직접 선택할 수 있습니다 — Terminal.app·iTerm2 가 손에 익혀 둔 바로 그 동작입니다.

같은 검토에서 지적된 리스너 정리 문제도 고쳤습니다. 누른 채로 창 포커스를 잃거나 패인이 사라지면 대기 중이던 press 를 버립니다. 그러지 않으면 나중의 드래그가 죽은 좌표로 재생돼 클립보드를 조용히 덮어쓸 수 있었습니다.

2차 검토는 그 정리 방식에서 **제가 회귀를 하나 만들어 놓고 PASS 라고 적어 둔 것**을 잡아냈습니다. 누른 채 포커스를 잃으면 대기 중이던 클릭을 그냥 버렸는데, 그러면 클릭이 통째로 사라집니다. 하필 이 문제가 나던 환경은 [Veraport 가 몇 초마다 포커스를 훔치는 PC](https://github.com/ChoiGyber/Mymux/issues/41) 라서, 메뉴 클릭이 무작위로 먹통이 될 수 있었습니다. 지금은 포커스를 잃어도 클릭을 정상 전달합니다.

| 정리 시나리오 | 결과 |
| --- | --- |
| 누른 채 창 포커스 상실 | **클릭이 press/release 로 정상 전달됨** (뒤늦은 release 가 클릭을 중복으로 만들지도 않음), 직후 정상 드래그도 그대로 동작 |
| 누른 채 패인 닫힘 | PTY 로 나간 바이트 0 · 클립보드 변경 0 · 예외 0 |
| 다른 패인을 누른 뒤 | 앞 패인에 선택이 생기지 않고 대기 상태도 남지 않음 |

## 알아 두실 부수 효과 두 가지

맥에서 강제 선택 옵션을 켜면서 **맥의 Option+드래그는 이제 vim 같은 TUI 로 가지 않고 터미널 텍스트를 선택**합니다. Terminal.app·iTerm2 와 같은 관례라 낯설지는 않겠지만, 의도된 동작 변경이라 적어 둡니다. 수식키 없는 일반 드래그는 예전처럼 TUI 가 그대로 받습니다.

그리고 클릭 트래킹을 쓰는 프로그램은 이제 버튼을 **누른 순간이 아니라 뗀 순간에** 클릭을 받습니다. 이 모드에는 그 사이에 전달할 마우스 이동이 없어서 대부분 차이가 없지만, 누르고 있는 상태를 그리거나 누른 시간을 재는 프로그램은 다르게 볼 수 있습니다.

## 수정

드래그를 되찾되 **클릭 전용 트래킹 모드에서만** 합니다. 그 모드의 프로그램은 press/release 만 요청했고 모션은 요청조차 하지 않았으므로, 드래그를 받지 못해도 잃는 것이 없습니다. 반대로 모션까지 요청한 프로그램(vim 의 마우스 비주얼 선택, htop)은 그대로 두었습니다. 화면 버퍼가 아니라 모드로 가른 이유는 Claude Code 가 일반 화면과 대체 화면 양쪽에서 트래킹을 켜기 때문입니다.

mousedown 시점에는 클릭인지 드래그인지 알 수 없으므로 press 를 일단 삼키고, 4px 를 넘어 움직이면 Shift 를 실어 재전달해 xterm 자신의 선택 경로로 넘깁니다. 움직이지 않고 떼면 press/release 쌍을 그대로 재전달하므로 Claude Code 메뉴 클릭은 계속 동작합니다.
