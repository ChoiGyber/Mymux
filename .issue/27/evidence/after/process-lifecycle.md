# after — 창을 닫으면 프로세스도 끝난다

빌드: `fix/27-exit-on-main-window-close` (main 창 `Destroyed` 에서 `handle.exit(0)`)
조건은 before 와 동일 — 새 WebView2 프로필, CDP 로 `closeAppWindow.destroy()`.

## 1. 종료 — 오버레이를 띄운 채로 닫아도 끝난다

before 보다 엄격한 조건으로 확인했다. `buddy_overlay_show` 로 데스크톱 캐릭터를 띄워
`buddy-overlay` 창이 **보이는 상태**에서 main 창을 닫았다.

```text
닫기 전
   Id Path
   -- ----
20044 D:\Project\Mymux\target\debug\Mymux.exe          ← 테스트 인스턴스
21236 C:\Users\ChoiGyber\AppData\Local\Mymux\Mymux.exe  ← 사용자 설치본 (건드리지 않음)

닫은 뒤 (5초)
   Id Path
   -- ----
21236 C:\Users\ChoiGyber\AppData\Local\Mymux\Mymux.exe
```

**테스트 인스턴스가 사라졌다.** before 에서는 같은 자리에 그대로 남아 있었다.

연속 실행 시나리오에서도 확인 — 닫은 직후 테스트 인스턴스 개수:

```text
0
```

## 2. 오버레이 회귀 없음

`buddy_overlay_show` → `buddy_overlay_hide` → 다시 `show` 를 CDP 로 호출하고, 오버레이 창의
DOM 을 직접 읽었다.

```json
{"cls":"show","char":"mascot","text":"'테스트 세션' 작업 다 끝났슈! 🎉"}
```

창이 뜨고, 마스코트 캐릭터와 충청도 사투리 말풍선이 정상 렌더링된다. `hide` 도 정상 응답했다.
이 수정은 오버레이를 없애지 않고 **앱이 끝날 때 같이 정리되게** 할 뿐이다.

## 3. 창 크기 저장·복원 회귀 없음 (#25 기능)

| 단계 | 앱이 인식한 크기(CSS px) | 실제 창(물리) | 저장값 |
| --- | --- | --- | --- |
| 첫 실행 | 1280 × 800 | — | — |
| 1400×900 으로 변경 | 1387 × 863 | 1734 × 1117 | — |
| 닫음 | — | — | `1732 × 1078 @ 63,50` |
| 재실행 | **1387 × 863 (복원)** | 1734 × 1117 @ 71,50 | — |

## 4. 연속 실행 — 최신 값이 남는다

이 이슈의 2차 피해(좀비가 낡은 값으로 덮어쓰는 것)가 사라졌는지 확인했다.

```text
실행 A: 1400×900 으로 닫음  → 저장 {width:1732, height:1078, x:63,  y:50}
실행 B: 1200×760 으로 닫음  → 저장 {width:1482, height:903,  x:125, y:88, prev_x:63, prev_y:50}
```

B 의 값이 그대로 남고 A 가 되살아나지 않는다. 각 실행이 자기 차례에 완전히 종료되므로
**낡은 캐시를 들고 있는 프로세스 자체가 존재하지 않는다.**

로그오프로 좀비를 깨우는 원래 시나리오는 재현하지 않았다. 좀비가 생기지 않는다는 것이
확인되면 그 시나리오는 성립할 수 없다.

## 검증 중 있었던 오탐 하나

중간에 저장값이 기본 크기(1600×1000 = 1280×800 의 물리 픽셀)로 남은 적이 있었다.
**코드 결함이 아니라 검증 타이밍 문제였다** — 리사이즈 직후 앱이 `Resized` 를 처리하기 전에
창을 닫아서, 캐시에 새 크기가 들어가기 전의 값이 저장된 것이다. 리사이즈 후 CDP 로 앱이
인식한 크기를 확인하고 나서 닫도록 절차를 고치자 정상으로 나왔다. 위 표의 수치가 그 결과다.
