## 저장 파일

`%APPDATA%/com.mycli.desktop/.window-state.json` — 물리 픽셀로 기록된다.

```json
{ "main": { "width": 1982, "height": 1203, "x": 50, "y": 25,
            "maximized": false, "visible": true, "decorated": true, "fullscreen": false } }
```

`width`/`height` 는 최대화 중에는 갱신되지 않는다. 최대화를 풀었을 때 돌아갈 크기를 잃지 않기 위한 플러그인의 의도된 동작이다.

## 검증에서 드러난 것 — 저장 시점을 Destroyed 로 옮긴 이유

플러그인은 파일을 **`RunEvent::Exit` 에서만** 쓴다. 그런데 이 앱은 거기까지 가지 않는다.
main 창을 닫아도 `buddy-overlay` 창이 살아 있어 프로세스가 남고, `Exit` 이 발생하지 않는다.
실제로 플러그인만 등록한 빌드에서는 창을 닫아도 `.window-state.json` 이 생기지 않았다.

그래서 main 창의 `WindowEvent::Destroyed` 에서 `save_window_state()` 를 직접 부른다.
플러그인이 `Moved`/`Resized`/`CloseRequested` 로 캐시를 계속 갱신하므로, 창이 사라진 뒤에
써도 마지막 실제 크기가 기록된다.

**앱을 닫아도 프로세스가 종료되지 않는 것 자체는 이 이슈와 별개인 결함이다.** 여기서는 고치지 않았다.
