## 원인 — 켜는 것은 ConPTY 다

화면에 찍히던 두 글자는 터미널 **포커스 리포트** `ESC[I`(DECSET 1004) 에서 앞의 ESC 가 빠진 잔해다.
codex 는 ESC 를 "취소" 로 삼키고 남은 두 글자를 평범한 입력으로 받는다.

실제 앱에 CDP 로 붙어 `Terminal.prototype.write` 를 후킹하고, **새 패인이 만들어지는 순간부터** 오가는 DEC private mode 시퀀스를 전부 기록했다.

```
?1004h  at 140926   ← 포커스 리포팅 켜기
?9001h  at 140926   ← win32-input-mode, 같은 시각
?1004l  at 141217   ← 291ms 뒤, 이 PR 의 수정이 끈다
```

**`?9001`(win32-input-mode)과 같은 시각에 온다.** 이건 셸도 TUI 도 아니라 **ConPTY 가 패인을 열면서 직접 켜는 것**이다.
같은 계측에서 새 패인의 `sendFocus` 는 **생성 직후 이미 켜져 있었다**(0ms 켜짐 → 200ms 켜짐 → 400ms 꺼짐).

그래서 **모든 패인이 태어날 때부터 포커스 리포팅이 켜진 상태**다.
codex 는 이걸 요청한 적이 없다 — 바이너리에 **비활성 시퀀스만 있고 활성 시퀀스는 아예 없다.**

```
?1004 : 1 회   →  ESC[?1004l (끄기) 만 존재
?2004 : 4 회   →  bracketed paste 는 켜기·끄기 둘 다 존재
```

xterm 은 DEC private mode 를 **패인 수명 내내** 들고 있고 아무도 되돌리지 않으므로, 켜진 상태가 그대로 유지되며 창 전환마다 리포트가 나갔다.

리포트가 하나가 아니라 겹쳐 보인 것은 창 복귀 한 번에 리포트를 만드는 경로가 **둘**이기 때문이다.
WebView2 가 주는 진짜 focus 이벤트 하나, 그리고 focus keeper 가 xterm 의 포커스 상태를 되살리려고 쏘는 **가짜** focus 이벤트 하나다.

## 수정

`crates/mycli-desktop/frontend/app.js` — 프런트엔드 전용, +52 줄.

1. **셸이 패인을 되찾으면 남은 1004 를 되돌린다.** `markPaneReturnedToShell()`(OSC 133;D) 에서 xterm 자신의 파서로 비활성 시퀀스를 먹인다. 다른 DEC 모드는 건드리지 않는다.
2. **대체 화면 이탈도 같은 신호로 쓴다.** OSC 133 마크가 없는 원격 셸(ssh) 대비. 들어갈 때는 아무것도 하지 않는다.
3. **focus keeper 의 가짜 focus 이벤트는 리포트를 만들지 않게 막는다.**

계측대로 첫 프롬프트가 그려지는 **291ms** 안에 정리되므로, codex 를 띄우는 시점에는 이미 깨끗하다.

## 실기 계측 (수정 적용 빌드)

실제 앱을 별도 프로필로 띄우고 전역 `invoke` 를 후킹해 PTY 로 나가는 바이트를 셌다.

| 항목 | 결과 |
| --- | --- |
| 새 패인의 초기 모드 1004 | 켜짐 → **291ms 뒤 정리됨** |
| 창 전환 시 나간 포커스 리포트 | **0 회** |
| 앱이 정당하게 1004 를 켠 상태 | 42 회 (리포트 경로는 살아 있다) |

마지막 줄의 42 회는 **이 PR 이 만든 것이 아니다.** focus keeper 가 250ms 마다 포커스를 되살리면서
그때마다 리포트가 나가는 기존 동작이고, 이 수정은 그중 가짜 이벤트 경로만 줄인다.
1004 를 켠 앱에게 리포트가 초당 몇 번씩 가는 것 자체는 **별도 이슈로 다룰 문제**다.

## 검증 방법과 한계

- 위 전후 캡처는 cargo 빌드 없이 실제 `app.js` 를 그대로 부팅시키고(Tauri IPC 스텁 하네스), 변경 전·후 코드를 **각각 별도 포트**에 띄워 같은 스크립트로 측정한 것이다.
- 캡처 왼쪽의 탐색기 오류와 빈 패널은 하네스 스텁의 한계다. 이 이슈와 무관하다.
- 실기 계측은 사용자 인스턴스를 건드리지 않고 `target/debug` 빌드를 별도 WebView2 프로필로 띄워 수행했다. 세션 파일은 계측 전후 해시가 같다.
- **사용자 환경에서의 최종 확인은 남아 있다** — 실제로 Claude Code 세션과 codex 세션을 오갈 때 더는 찍히지 않는지.
